本次针对 RTX 5090 Laptop 的 8K 拼接实测继续提速。用户提供的单路纯解码结果约为

5.0.11 在 NVIDIA 官方列出双 NVDEC 的 RTX 5080/5090 台式及 Laptop 型号上，默认把剪辑重编码设为 2 路：

- 先按最终时间轴把长画面拆成约 4–5 个连续、帧精确的小段，两条 FFmpeg 任务动态领取；
  每个任务只打开一个相机源，仍使用 CUDA 显存路径、当前码率、P1/P2/P4/P6、位深及多 NVENC 设置。
- 两条独立 CUDA 解码会话可分别使用两个 NVDEC。分段完成后按原顺序使用 `-c:v copy` 合并视频码流，
  只在最后一步编码一次连续主音频；视频不会二次压制，黑场、紧凑模式和首尾裁切保持原时间轴语义。

  5.0.10 的单路直接导出。以本次 `30M × 10858.48 秒` 为例，双路模式预留约 83.5 GiB。

## 5.0.10 剪辑导出提速更新

关闭软件，将本次覆盖更新包中的文件放入原软件目录，覆盖同名文件，再双击 `start.bat`。
窗口标题应显示 **5.0.10**。使用独立 EXE 的用户需在原目录运行 `build_exe.bat` 重新构建；
本包没有预编译的新 EXE。原有 `bin`、`assets` 与达芬奇连接器目录继续使用。

- **只读取最终保留区间**：先计算成片开始/结束、录音边界和停机空窗；不在成片内的视频不打开，
  保留片段使用输入侧精确定位。定位时仍需解码入点前的最近一段 GOP，但不会从原片开头一路解码后再丢弃。
- **显存内拼接**：选择 CUDA 解码时，支持的素材通过共享 CUDA 设备进入时间轴与 NVENC；
  原分辨率、同位深的常见 4:2:0 素材不再逐帧下载回内存做 `tpad` 和格式转换。
  黑场只生成并上传一帧，再重复使用；调整分辨率/位深时优先使用 `scale_cuda`。
  缺少所需 CUDA 缩放能力时采用内存兼容路径，日志会注明实际路径。
- **一次输出**：视频只执行一次最终编码，主音频同时写入成片；对齐重编码不产生中间视频，
  并取消末尾 `faststart` 整文件重排。本地播放、剪辑导入正常，在线边下载边播放需另做 faststart。
- **直接取主音频区间**：连续模式只定位一次主音频；紧凑模式按需要定位对应区间，
  不再对整条长录音进行 `asplit` 缓存。每段单独补足尾部静音，避免后续声音提前。
- **进度清晰可见**：底部进度条加粗，百分比居中显示。`0.2%` 仍按真实比例填充，文字始终可见。
  剪辑导出和批量代理显示最近约 3 秒的 FPS 与倍速，第一份有效数据前的等待不计入近期速度。
  刚开始尚无足够样本时显示 0；音频任务的 FPS 为 0，倍速仍有效。
- 导出开始时暂停预览，减少预览解码与导出争用。
- 保留现有预设、码率、CQ、位深、多 NVENC、黑场、音频格式与采样率设置；不会为了速度自动降低画质参数。

时间轴按素材帧率输出，裁切及空窗边界取到最近一帧；对累计边界统一取整，避免多段拼接累计偏移。
日志中的“导出路径”和“剪辑导出命令”可用于检查实际执行的参数。

这是 OKK GROUP 面向 Windows 11 与 NVIDIA GeForce RTX 20/30/40/50 系显卡制作的 FFmpeg 图形化视频工具，Laptop GPU 和台式显卡均可自动适配。默认管线为：

4.0.0 不再把硬件写死为 RTX 5090。软件启动时会读取 GPU 完整型号、Laptop/台式形态、显存、驱动版本，以及当前 FFmpeg 真正提供的 NVENC/CUDA 能力，然后自动配置：

- 可选编码器：只显示当前 FFmpeg 实际支持的 H.264、HEVC、AV1 NVENC。
- 多 NVENC 分帧：单引擎型号自动关闭；双/三引擎型号为 HEVC/AV1 选择对应的 2/3 路模式。

4.0.1 将代理文件改为 DaVinci Resolve 标准命名：代理保存在独立 `ProxyMedia` 文件夹中，主文件名与原片完全相同，只将扩展名改为 `.mp4`。例如 `C2745.MOV → ProxyMedia/C2745.mp4`，可在媒体池中批量选择原片后直接链接整个代理目录。软件会阻止代理覆盖同目录下的 MP4 原片。

5.0.6 修复窗口底部按钮行在部分分辨率或 Windows 显示缩放下被压扁、文字只显示一部分的问题。底部状态栏现在会先从窗口底部保留完整自然高度，中间的主页面使用剩余空间并优先缩放；“10 秒性能测试”“复制 FFmpeg 命令”“开始导出”和“取消任务”会始终完整显示。

5.0.7 在“拼接 / 换音”中增加完整的成片尾部处理。默认在连续主音频结束时同步裁掉剩余画面，避免导出后出现“画面还在但已经没有声音”；也可选择保留结尾画面并自动填充静音。新增“成片开始 / 成片结束”手动时间，使用最终输出文件的 `HH:MM:SS.mmm` 时间轴，留空保持自动，填写后覆盖对应自动边界。MPV 对齐试听与最终一次 RTX 导出使用同一范围。

5.0.8 修复部分 Windows MPV 构建在对齐试听时提示 `error accessing property` 的兼容问题。试听终点改由软件自身监控，到达设定结尾会自动暂停，不再写入 MPV 不支持的 `end` 属性。播放器新增前进/后退 10 秒精确跳转，同时完整保留前后逐帧按钮。

本次 5.0.8 维护更新将所有图形界面导出任务统一接入窗口底部的主进度条：普通导出、裁切、拼接/换音、替换音频、音视频分离和批量 1080p 代理均显示实时百分比与速度。音视频分离按“视频 1/2”和“音频 2/2”连续计算总进度，第二阶段不会将主进度条重置为零。

同一维护更新新增 GeForce RTX 20/30 系台式与 Laptop 通用适配。RTX 2050/2060/2070/2080 和 RTX 3050/3060/3070/3080/3090 各 Ti、SUPER、Max-Q 变体均可识别；软件将它们设为单 NVENC，允许 H.264 与 HEVC 10-bit，并自动隐藏硬件不支持的 AV1 编码。

底部主进度的实时通道进一步改为独立读取 FFmpeg `-progress` 数据，不再与警告/日志混用同一管道；默认每 0.25 秒刷新一次，同时显示“总百分比 · FPS · x 倍速”。`start.bat` 会优先启动当前 Python 源码，防止旧版 EXE 遗留在文件夹时掩盖新修复。

本压缩包是 5.0.8 的 DaVinci 连接版，对 RTX 20/30 系使用统一通用适配，不是 RTX 3070 单型号专用版。新增 `OKK Export` 达芬奇菜单、无界面 NVENC 导出入口及一键安装/卸载脚本。连接器会把当前时间线先渲染为 QuickTime/DNxHR HQX 中间母版，再调用本软件直接输出 MOV/H.265；用户可设置目标码率、CQ、P1/P2/P4/P6、8/10-bit、音频处理，以及是否在成功后删除临时母版。

## 安装 DaVinci 连接器

1. 将整个软件文件夹解压到固定位置，不要安装后再随意移动。
2. 像以前一样，把 `ffmpeg.exe`、`ffprobe.exe` 和可选的 `mpv.exe` 放进 `bin` 文件夹。
3. 双击 `一键安装达芬奇连接器.bat`。
4. 完全退出并重新打开 DaVinci Resolve。
5. 打开项目和时间线，进入 `工作区 → 脚本 → OKK GROUP → OKK_Export`。
6. 选择最终 MOV 文件，填写 H.265 目标码率、位深、CQ、预设和音频方式，然后点击“开始 OKK 导出”。

如果菜单没有出现，先检查以下文件是否存在：

```text
%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Scripts\Utility\OKK GROUP\OKK_Export.py
```

达芬奇官方脚本文档可在 `帮助 → 文档 → 开发者` 中打开。Workflow Integration、Encode Plugin 和外部脚本控制能力会受到 DaVinci Resolve 版本与授权类型限制。

### 连接器实际流程

达芬奇的 Python API 不能把调色节点、Fusion 和时间线效果直接交给 FFmpeg，也不能直接替换交付页内部编码器，因此连接器分为两个自动阶段：

1. DaVinci Resolve 自动将当前完整时间线渲染为 QuickTime/DNxHR HQX 临时母版。
2. `rtx5090_exporter.py --headless-export` 自动读取母版，并通过 RTX NVENC 输出最终 MOV/H.265。

DNxHR 不属于 NVDEC 支持的解码格式，因此中间母版读取会使用 CPU；H.265 编码仍由 NVENC 完成。若勾选“成功后删除临时母版”，软件只会删除带有 OKK 安全标记、位于系统临时目录中的连接器母版，不会删除用户手动选择的素材。

## 导出与加速

- 8K/4K HEVC 快速交付：P1/P2、CQ 20–23、自动/10-bit、CUDA 解码。
- 双/三 NVENC 型号：软件会为 HEVC/AV1 自动选中对应的强制分帧模式。
- 单 NVENC 型号：软件会关闭多引擎分帧，避免无效参数和额外调度开销。
- H.264 不使用硬件分帧；批量 1080p 代理依靠多个编码会话提高队列吞吐。
- “并行分段任务数”与硬件分帧不同。普通单片导出优先保持 1，只有实测更快时再升到 2–4。

NVENC/NVDEC 是独立视频硬件，不等同于 3D/CUDA 核心。判断是否跑满时，应优先观察软件里的“视频编码”“视频解码”和实际导出倍速，而不是任务管理器默认的 3D 百分比。

## 剪辑工具

1. 打开“剪辑工具”，选择视频，或点击“使用导出页素材”。
2. 使用统一 `HH:MM:SS.mmm` 时间码播放、跳转、前进/后退 10 秒及前后逐帧。
3. “截取当前帧（JPG）”通过 MPV 当前 GPU 显示色彩输出原分辨率、质量 98 的 sRGB JPEG。
4. “裁切”支持逐帧精准 NVENC 重编码和关键帧无损快速裁切；精准模式可沿用导出页设置并指定目标码率。裸数字 `40000` 会按 `40000k` 处理，也可直接填写 `40M`。
5. “拼接 / 换音”支持同规格视频排序拼接、连续主音频逐段自动/手动对齐、停机空窗黑场保留或紧凑删除，以及 RTX 一次直接导出。该页已经完整集成预设、分辨率、位深、CQ、目标/最大码率、解码路径和多 NVENC 分帧；主音频可独立设置 AAC 码率、采样率或 PCM 16/24/32-bit 位宽。右侧页面可使用鼠标滚轮向下查看全部选项。
6. “音视频分离”可分别输出视频轨和 MKA/WAV/FLAC/AAC 音频。
7. “1080p 代理”可一次提交 20–30 个或更多 4K/8K 原片，统一输出到 `ProxyMedia` 文件夹。代理与原片主文件名相同，例如 `C2745.MOV → C2745.mp4`。在 DaVinci 媒体池中选中对应原素材，右键“链接代理媒体”，选择整个 `ProxyMedia` 文件夹即可批量匹配。

上述所有长时间导出都共用软件底部的主进度条；在“拼接 / 换音”页开始任务后，可直接在底部查看准备状态、实时百分比和 FFmpeg 处理速度。

自动对齐优先使用 NumPy 高速 FFT；未安装 NumPy 时自动切换到内置兼容 FFT，不需要额外安装。若长演唱会录音分析较慢，可双击 `install_audio_alignment.bat` 安装 NumPy。

### 演唱会分段拼接工作流

1. 在“剪辑工具 → 拼接 / 换音”中按拍摄顺序添加尼康生成的所有分段。
2. 选择从开场持续录到结束的 WAV、FLAC 或其他主音频，点击“自动对齐全部片段”。列表会显示每段在主音频中的真实起点和匹配可信度。
3. 选中一段后点击“试听对齐结果”，或直接双击列表中的片段。左侧监看会播放该段画面与定位后的主音频；建议重点试听第二段开头。自动定位不够准时，可在“手动对齐”中填写该段对应主音频的 `HH:MM:SS.mmm` 时间，或填写移动秒数后点击“提前/延后”进行微调，再次试听。
4. 如果第一段视频早于主音频开始，在“主音频开始前”选择处理方式：“裁掉开头画面”会自动从录音开始的对应帧起算；“保留开头画面”会保留完整视频并在这段时间保持主音频静音。手动设置时可输入负时间码，例如 `-00:03:10.620`。如果最后一段画面晚于主音频结束，“主音频结束后”默认同步裁掉结尾画面；也可保留剩余画面并让后段静音。
5. 在“视频封装 / 编码”中直接选择 `MOV / HEVC H.265（NVENC）`、MP4、H.264 或 AV1；输出文件扩展名会自动同步。继续向下滚动即可设置预设、分辨率、8/10-bit、CQ、目标码率、最大码率、CUDA/CPU 解码和多 NVENC 分帧。填写视频目标码率时使用目标码率输出；留空则使用 CQ。
6. 默认选择“保留停机空窗”，空窗显示纯黑画面，主音频连续播放。如需精确控制成片，可填写“成片开始 / 成片结束”；这里的 `00:00:00.000` 从最终导出文件第一帧开始计算，留空则采用自动边界。选择主音频输出格式、采样率、AAC 码率和输出文件，点击页面最下方“对齐、拼接并导出”。`48k/96k` 在采样率栏表示 48/96 kHz；AAC 码率栏的 `48k/96k/320k` 表示每秒压缩码率。PCM 16/24/32-bit 不使用码率，输出容器请选择 MOV 或 MKV。涉及开头、结尾或手动范围的逐帧裁切请选择 RTX 重编码；全程仍只执行一次最终导出，不会先生成无损成片再压缩第二遍。

保留空窗模式会从第一段在主音频中的位置开始连续取音频，并根据两段的真实时间差插入等长黑场；因此停机期间仍能听到主录音，第二段之后也不会累计偏移。若改选“删除停机空窗”，软件才会按每段对应区间重组音频；这一模式可配合“无损复制视频流”。相机每段必须保留可供匹配的现场参考音轨。

## 与 DaVinci Resolve 配合

本软件不能替换 DaVinci 内部解码器，也不能读取 `.drp` 工程、Fusion、调色节点或时间线。推荐两种用法：

1. 用批量代理模块生成 1080p ProxyMedia，在 DaVinci 中链接代理后剪辑。
2. 从 DaVinci 导出高质量母版，再用本软件快速压制交付版 HEVC/AV1。

## 常见报错

- `No capable devices found`：更新 NVIDIA Studio Driver，接通电源，并在 Windows 图形设置中把程序设为高性能 NVIDIA GPU。
- 找不到 `h264_nvenc/hevc_nvenc/av1_nvenc`：换用包含 NVENC 的完整 Windows FFmpeg 构建。
- 找不到 `split_encode_mode`：当前 FFmpeg 较旧，软件会回退到驱动自动调度；升级 FFmpeg 后可启用明确的多引擎分帧。
- CUDA 解码失败：切换为“CPU 解码（兼容模式）”，编码仍会使用 NVENC。
- 剪辑页提示缺少 MPV：把可独立运行的 `mpv.exe` 放入 `bin`，重启软件。
- 多段对齐可信度过低：确认每个相机片段带有现场参考音轨，并先裁掉长时间纯静音或完全不同的内容。
- 硬盘成为瓶颈：原片、代理与中间文件尽量放在内置 NVMe SSD。
